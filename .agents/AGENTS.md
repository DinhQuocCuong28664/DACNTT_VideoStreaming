# AGENTS.md — Cloud-Native Video Sharing Platform (DACNTT_VideoStreaming)

## 1. Project Overview & Context
This repository contains the IT Project (DACNTT): **"Building a Video Sharing Platform with an Automated HLS Transcoding Pipeline on Serverless Container and Event-Driven Architecture"** (Khoa CNTT, Trường Đại học Tôn Đức Thắng).
- **Team:** Đinh Quốc Cường (523H0008) · Võ Huỳnh Minh Đức (523H0014)
- **Advisor:** ThS. Mai Văn Mạnh
- **Production Domain:** `https://zelostech.site`
- **GitHub Repository:** [https://github.com/DinhQuocCuong28664/DACNTT_VideoStreaming](https://github.com/DinhQuocCuong28664/DACNTT_VideoStreaming)
- **Core Architectural Invariants:**
  - **Serverless Transcoding:** Transcoder runs strictly on AWS Batch Fargate (Spot/On-Demand) compute environments, terminating immediately when queue is empty (eliminating idle cost). No long-running EC2 instances for video processing.
  - **Direct-to-S3 Upload:** Client uploads raw videos directly to the S3 Raw Bucket via Pre-signed URLs (15-min TTL) generated by the Backend, eliminating upload proxy bottlenecks.
  - **Private Processed Bucket & CloudFront OAC:** Processed video segments (`.ts`) and playlists (`.m3u8`) are kept private and accessible strictly through CloudFront with Origin Access Control (OAC).
  - **SQS Heartbeat Pattern:** The transcoding container must maintain an active heartbeat loop extending SQS message visibility timeout during long-running FFmpeg transcode jobs to prevent duplicate worker execution.
  - **AWS Accounts Policy:** Prioritize AWS Account B (`749680934725`, profile `default`). Never create paid resources in Account A (`911707244328`) without explicit user permission.

### 3.1. 🏗️ `@architect` — System Architect & Tech Lead
- **Scope:** End-to-end architecture, event-driven orchestration (S3 $\rightarrow$ SQS $\rightarrow$ Batch Fargate $\rightarrow$ S3 $\rightarrow$ CloudFront), API contracts, data models, AWS quota governance.
- **Key Responsibilities:**
  - Preserve the serverless boundary: ensure no compute instances remain idle when no videos are uploading.
  - Enforce AWS Account B quota limits (`749680934725`) and run `python ~/.claude/aws-quota-report.py` when modifying infrastructure.
  - Oversee consistency across MongoDB models (`Video`, `User`, `Comment`, `Channel`, `Report`).

### 3.2. ⚡ `@transcoder-pipeline` — Media & Containerization Engineer
- **Scope:** `transcoder/` directory (Docker, FFmpeg, HLS packaging, worker script, SQS consumer).
- **Key Responsibilities:**
  - Maintain multi-stage Docker build with `node:18-slim` (glibc compatibility for FFmpeg).
  - Generate HLS renditions (up to 6 variants: 144p, 240p, 360p, 480p, 720p, 1080p, bounded by source resolution) with 6-second segments and master `.m3u8`.
  - Maintain the Heartbeat Pattern loop during FFmpeg execution to continuously extend SQS Visibility Timeout, preventing duplicate job execution.
  - Update MongoDB video record on completion to status `READY` with CloudFront HLS master playlist URL.

### 3.3. 🌐 `@backend-api` — API Services & Cloud Integration Engineer
- **Scope:** `backend/` directory (Node.js Express, MongoDB Atlas Mongoose, AWS SDK v3, JWT Auth).
- **Key Responsibilities:**
  - Maintain layered architecture: `routes/` $\rightarrow$ `controllers/` $\rightarrow$ `services/`.
  - Issue Pre-signed URLs for direct S3 upload with 15-minute expiration.
  - Handle video lifecycle status: `UPLOADING | PROCESSING | READY | ERROR`.
  - Enforce view-count validation rules: count a view only after 30 seconds of confirmed continuous playback.
  - Manage user authentication, profile management, comment moderation, and report triage workflows.

### 3.4. 🎨 `@frontend-player` — Web UI & Adaptive Video Player Specialist
- **Scope:** `frontend/` directory (React 18 SPA, HLS.js adaptive player, Tailwind / CSS).
- **Key Responsibilities:**

  - Upload Interface: Multi-part direct upload to S3 using Pre-signed URLs with real-time upload speed, ETA counter, and cancel button.
  - Channel Management & Watch Page: Video editing modal, comment section with reporting modal, related video recommendations sidebar, dark/light theme toggle.

## 4. Engineering & Workflow Conventions

1. **Language Discipline:**
   - **Code, identifiers, commits, logs, technical tests:** Strictly in **English**.
   - **Reports, summaries, explanations, reviews for users:** Strictly in **Vietnamese** (`english-code-vietnamese-response`).
2. **Git Commit Standards:**
   - Conventional Commits: `type(scope): concise description` (e.g. `feat(backend): add pre-signed URL endpoint`).
   - Primary working branch: `master`.
3. **Windows Environment Essentials:**
   - Python text mode newline handling: use `newline=""` or send bytes (`windows-python-newlines`).
   - PowerShell & console encoding: explicitly use UTF-8 (`windows-utf8-encoding`).
   - Git Bash paths: prepend `MSYS_NO_PATHCONV=1` when calling Docker CLI (`git-bash-path-conversion`).
4. **Verification Protocol:**
   - Backend verification:
     ```bash
     cd backend && npm test
     ```
   - Transcoder verification:
     ```bash
     cd transcoder && npm test
     ```
   - Frontend build verification:
     ```bash
     cd frontend && npm run build
     ```
   - Report compilation verification:
     ```bash
     cd report && pdflatex -interaction=nonstopmode main.tex && bibtex main && pdflatex -interaction=nonstopmode main.tex && pdflatex -interaction=nonstopmode main.tex
     ```
